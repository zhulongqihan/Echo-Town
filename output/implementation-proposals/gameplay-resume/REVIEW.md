# v7 当前阶段接入补丁（2026-10-15）

当前正式代码把每个 v7 当前阶段都视为旧制，导致 6 岁开局也无法取得童年新成果。本提案只在存在一条可验证的剩余操作路径时接入当前目标。

## 实现

- `migration-helper.js`：放入 Engine 闭包；克隆候选存档，通过现有 `dispatch()`、`previewAction()` 尝试每路线最多五种固定安排。仅执行尚未发生的普通行动，不使用机会收益、购买或不确定检定。未来检定仅当行动前预览的最低得分已达到难度时才可作为证明，与随机种子无关。每个被接入目标都有一条可以重新执行并确实取得成果的命令见证。
- 原始存档的资源、行动点、机会牌、已选事件、反馈、账本余额、历史和随机种子均不改变。投影结束以 `finally` 恢复 Engine 的全部闭包状态与待发事件；Engine 自身只产生事件，投影不会触发保存、音频或界面消费者。
- `migration.goalAccessVersion = 1` 固化本次接入决定；`activeGoalIds` 仅包含迁移时当前阶段的 0–3 个目标。之前的阶段全部旧制；当前不能证明的目标仍旧制；后续完整阶段正常接入。
- 中途反馈只允许前进到下一未发生节点，不重做当前事件。阶段末反馈、75 岁最终反馈和已结算人生不再接入当前目标。已生成结局不改写。
- 旧 flags、日志、技能和物品不会冒充新版行动证据；所有新证据必须由迁移后真实操作产生。

## 审阅与集成

`install-proposal.cjs` 导出 `patchEngine`、`patchStrategy`、`patchSave`。锚点不唯一或缺失即报错，不会静默覆盖其它改动。

主 Agent 可在审阅后读取三个当前正式源，调用对应补丁函数写回。脚本命令行模式必须提供明确输出目录，只向该目录生成三个文件，不默认修改正式源码。`patched-runtime/` 是本次校验用的生成副本，不应整体覆盖主 Agent 已继续修改的源代码。

`migration-access.test.js` 当前通过 VM 为正式代码应用补丁验证；集成到正式测试目录时，应去掉 `patches` 与补丁安装依赖，直接读取已集成源。测试专用 `__migrationProof` 暴露只存在 VM 源文本中，不应作为正式公共 API。

旧 `output/implementation-proposals/strategy/natural-routes.test.js` 和 `strategy-behavior.test.js` 已完整，可直接集成到同一测试目录。两者通过向上寻找 `development/game/content.js` 定位仓库。

## 已验证

2026-10-15：新迁移测试 9 项，加旧路线/行为测试 13 项，在已应用补丁的隔离运行时共 **22/22 通过**。

- 三路线各 5/5 阶段成果，三个成功链结果各记录一次；没有初始遗产、直接属性注入或机会重抽。
- 全路线结局无债务，健康 10；手艺/学业/关系最终压力分别 4/3/3。
- 迁移覆盖童年开局、中途、少年末、青年末、中晚年、AP 0/1/2、精力 0、未选机会、事件反馈、75 岁最终反馈、完整结局；已接受目标的普通命令见证逐一在迁移后重放成功。
- 真实接入反例：11 岁、手艺 1、精力 0 时，AP 0 没有可用修理机会，AP 1 可以休息再修灯笼；即使学识 9 且旧 flag 含 front-seat，仍不会凭旧 flag 授予童年学业成果。
- 投影无磁盘写入；刷新、转线、修改后续状态不会重新打开已固定的旧制目标。
- 中年手艺 10、现金充足的旧档有实际见证：36 岁保证成功开作坊，较晚节点做修理工作，阶段末留够下一笔生活费。四个不同种子均可接入。所有优先事件 ID（含 learn-bicycle、fix-bicycle、study-plan）均对真实节点逐项验证。

## 明确边界

这是充分条件证明，未声称穷举所有可能路线。存在需要机会收益、购买、不确定检定或更复杂行动顺序才能完成的当前目标时，保守保留旧制，下一完整阶段启用新目标。这里不把“没找到证明”描述成数学上的“不可能完成”。

固定路径只是迁移准入见证，不会替玩家执行、授奖或推荐刷同一种行动；实际接入后玩家仍可自由安排并可能错过目标。
