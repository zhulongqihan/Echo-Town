# 仓库同步与交付

仓库：[zhulongqihan/Echo-Town](https://github.com/zhulongqihan/Echo-Town)。远端 `origin`，交付分支 `main`。用户要求在每个完成阶段及时提交推送（EVENT-20260829-011、EVENT-20261023-028）。

## 需要同步的内容

- 根入口、README、PRODUCT、AGENTS、Git配置文件。
- `development/` 正式源码、实际加载的WebP/SVG素材、内容清单、存档契约和测试。
- `planning/` 权威决策、任务、当前状态与交接；`docs/` 运行说明和当前恢复入口。
- `output/releases/` 最终ZIP和同名清单；测试依赖的固定样例与交接所需的审查证据。

原始图片、本机备份、未整合提案、浏览器临时档案可以留在本地。不能把未提交的文件作为运行或测试的隐含依赖。个人Codex配置和任何凭据不属于仓库配置。

## 完成一个阶段

1. 核对 `git status`、当前分支和 `git ls-remote origin refs/heads/main`；保留用户与其它任务的材料。
2. 完成与改动相符的验证。修改运行资源时递增缓存版本；修改内容时同步内容版本与审阅清单；涉及存档时验证兼容与导入失败保护。
3. 更新玩家说明、开发契约和当前状态，构建离线包并核对入口/运行文件哈希。
4. 明确暂存文件，检查遗漏的模块、素材、样例和文档链接。必要时从暂存树导出干净副本，确认可运行且校验通过。
5. 提交并 `git push origin main`；推送被拒绝时先检查远端变化，不使用强制推送。
6. 比较 `git rev-parse HEAD` 与 `git ls-remote origin refs/heads/main`。两者一致后才能报告当前提交已同步。

源码推送、ZIP交付、GitHub Release与在线网站是不同产物；没有部署操作与可访问网址时，不报告“已上线”。

历史总结中的“不自行提交/无推送要求”已纠正，不得继续作为约束。当前恢复入口只引用一份状态摘要，避免重复抄写导致授权或版本漂移。
