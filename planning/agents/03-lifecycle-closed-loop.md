# Agent 生命周期与闭环协议

## 一轮工作的完整状态机

`未启用 → 可启动 → 工作中 → 待审查 → 已完成 → 退出`

异常分支：

- 上游变化：`工作中/已完成 → 需重开`
- 冲突或越权风险：`工作中 → 暂停`
- 审查不通过：`待审查 → 工作中`，必须携带明确问题清单

## 九步闭环

1. **对齐**：读取总入口、角色宪法、状态、任务简报和锁定上游。
2. **复述**：在动笔前明确事实、假设、待决策、写入范围和验收。
3. **产出**：只处理任务的唯一主问题，不顺手扩展下游设计。
4. **自审**：按玩家、产品、专业、技术可实现性、范围五个维度检查；A07另加可测试性与回归影响。
5. **提案**：跨越自身所有权的建议写为`PROPOSAL`，不直接修改他人正文。
6. **交付**：更新所属专题草案、写`REVIEW`与`HANDOFF`，列出变更、证据、开放问题和精确下一步。
7. **回写状态**：更新自己的`STATE.md`；这是每轮完成的硬条件，不回写即视为未交付。
8. **限次修订**：初稿不通过时，只按问题清单发起修订；每个任务最多两轮聚焦修订，仍未解决就升级阻塞。
9. **整合退出**：A00核对、提交用户决定、锁定或退回；角色状态改为已完成并退出活动状态。

## STATE.md必填内容

- `as_of`、当前状态、当前任务、任务简报链接。
- 本轮读取的上游文件及版本。
- 已完成事项与实际修改文件。
- 事实、假设、推断、待决策分别列出。
- 收到/发出的提案与处理状态。
- 自审结论、已知风险、阻塞项。
- 最新交接、下一次启动的第一动作。
- 本轮初稿/修订轮次和剩余修订预算。

## 完成定义

一个角色说“完成”不等于门禁通过。只有以下全部满足，本轮才闭环：

- 任务简报的交付物齐全并通过自审。
- 没有越权写入或未登记的跨角色结论。
- `STATE.md`与最新`HANDOFF`已更新，时间不早于专题文件。
- A07或指定审查者完成独立审查。
- A00完成影响追踪；需要用户决定的事项已集中提出。
- 用户确认后，A00才更新决策日志、总入口和门禁状态。

## 防空转规则

- 连续两轮只改措辞、未减少开放问题或未提高可验证性，A00应暂停角色并缩小任务。
- 同一阻塞连续三轮无新增证据，转为阻塞升级，不得重复生成同类分析。
- 未产生文件变更的讨论可以有价值，但必须在`STATE.md`记录“为何不改”及下一验证动作。
- 每个门禁完成后，A00必须在主窗口集中汇报并等待用户确认；不得悄悄跨过用户门禁继续推进。

## 调度可靠性与延迟写入规则

- 任务启动后必须先写入“已接单/工作中”状态，再开始长时间分析；不得只在聊天中确认接单。
- A00等待内部实例的时间不是任务完成条件。实例无最终消息时，必须以任务文件、专题文件、STATE和HANDOFF是否齐全为准。
- 关闭或替换实例前，A00必须执行一次文件扫描；关闭后若出现迟到写入，必须把该写入标记为“待验证”，不得自动纳入项目事实。
- 同一任务只能有一个有效实例；恢复时沿用原角色身份，回收旧租约后签发新租约。
- 任务的完成条件必须由项目校验器检查；聊天最终回复不能替代文件交付。
