# 未来 Agent 启动顺序与操作手册

## 总原则

不是一次启动七个角色。每个角色只在上游已锁定、任务可被清楚验收时启动；完成交接后退出，后续需要时再用同一角色身份恢复。

A07可以在某份专题进入“审查中”时短时启用，但它不得与主写角色共同编辑专题正文。

## 每次调度前，A00必须完成

1. 检查总入口和最新交接是否新鲜，扫描比 `as_of` 更新的用户修正。
2. 验证启动门禁与全部上游状态；存在未锁定依赖则停止。
3. 在目标角色目录创建一份 `TASK_YYYYMMDD_NNN.md`，写明唯一主问题、输入版本、允许写入文件、交付物、验收、截止门禁和停止条件。
4. 把注册表状态改为“可启动”，确认没有其他主写租约。
5. 用户在主窗口授权开始或继续规划后，A00可以自动调度当前角色；不再要求用户逐个输入“启用 Axx”。
6. 优先使用内部 Agent 任务执行；平台允许时显示任务，无法显示时仍以文件记录为准。

### 调度失败的确定性兜底

- 实例必须先把任务状态和`STATE.md`写成“工作中”，再进行长分析。
- 若在规定等待窗口内没有状态回写、任务文件或交付文件，A00不得继续等待并把它当作正常进度；应回收租约、记录`revoked_reason`，并按任务指定的兜底方式恢复。
- 兜底顺序固定为：同一角色新实例接班 → A00在授权范围内临时接管 → 暂停并向用户报告。临时接管不得伪装成专业审查。
- 实例关闭后出现迟到写入，按`04-conflict-change-exit.md`的“待验证”规则处理。

## 未来给新对话的首条指令

> 你是《回声镇：一生一局》的【Axx 角色名】。先完整读取 `planning/00_master-index.md`、最新根交接、`planning/agents/Axx-目录/AGENT.md`、`STATE.md`、最新 `TASK_*.md` 及任务中列出的上游权威文件。先复述任务、写入权限、上游版本、验收条件和停止条件；发现冲突就暂停报告。确认无冲突后再工作。每轮结束必须更新自己的 `STATE.md`，写一份 `HANDOFF_*.md`；不得修改自己的 `AGENT.md`、总入口、决策日志或其他角色文件。

## 用户日后怎样控制

用户只需在A00主窗口使用自然语言：

- “开始规划”或“继续规划”：A00自动推进当前门禁。
- “暂停规划”：回收在途租约，保存状态，不再派发新任务。
- “确认当前门禁”：记录用户确认并进入下一门禁。
- “退回修改”：A00根据审查问题发起聚焦修订。
- “重开这个决定”：A00暂停受影响下游并建立变更记录。

A00先生成任务简报并检查门禁，再调度当前角色。用户不需要知道角色对话是否在界面中可见，也不需要单独管理角色窗口。

## 恢复而非重建

- 同一角色换新任务实例时，身份仍是同一个Axx，不新增Axx-2。
- 新实例读取`STATE.md`与最新`HANDOFF`后接班，并将旧对话标识记入历史。
- 聊天记录不是权威记忆；未写入文件的结论视为未交付。
