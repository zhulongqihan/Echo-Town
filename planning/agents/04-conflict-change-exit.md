# 冲突、变更、替换与退出协议

## 冲突分级

- P0：违反用户明确约束、锁定决策、唯一权威来源或造成不可恢复的数据/范围风险。立即暂停相关工作。
- P1：影响门禁、核心体验、跨模块接口或内容规模。不得带入下游，必须在当前门禁解决。
- P2：局部表达、非关键偏好或可延后的优化。记录后由文件所有者处理。

## 解决顺序

1. 定位冲突的两份原文与版本，不先争论结论。
2. 按权威顺序判断是否已有唯一答案。
3. 若没有答案，双方各写一份最短提案，包含玩家影响、成本、风险、可验证方式。
4. A00做跨模块影响分析；A07检查可测试性与隐藏成本。
5. 涉及玩家承诺、范围、商业、世界真相、核心规则或门禁的，由用户决定。
6. 决定后先更新决策日志和权威专题，再标记/重审派生文件。

禁止用“折中一下”掩盖互斥规则，也禁止让最后写文件的人自然胜出。

## 角色宪法变更

角色不能自改`AGENT.md`。如职责不够或不合理：

1. 角色写`PROPOSAL`说明缺口、证据、所需新权限和潜在冲突。
2. A00检查是否可通过调整任务而非扩权解决。
3. 必须扩权时，登记变更申请并列出受影响角色、文件和在途任务。
4. 用户确认后，由A00修改宪法与注册表，旧版本保留在变更记录中。

## 暂停与恢复

暂停时，角色先更新`STATE.md`和`HANDOFF`，不得继续写专题。恢复前，A00重新核对上游版本并签发新任务简报；旧租约不会自动恢复。

## 单窗口调度异常

- A00调度失败或平台不显示内部任务时，不把任务标记为完成；保留 `STATE.md` 的“待启动/中断”状态，并由 A00 重新调度同一角色身份。
- 内部 Agent 的可见性不是项目事实；任务文件、专题文件、状态和交接记录必须完整，主窗口才能继续推进。
- 用户只在门禁和高影响决策处介入；角色执行过程中的普通判断由 A00 按红线和任务租约处理。

### 迟到写入与实例关闭

- 实例关闭后出现的文件变更一律进入“待验证”状态，A00先比较任务签发时间、租约状态、文件版本和修改时间。
- 若变更发生在租约回收后，不能直接覆盖当前权威文件；先复制为审查材料或建立PROPOSAL，再由文件所有者和A00决定是否吸收。
- 任何无法确认来源的修改都不计入交付；必须在用户事件、交接或审查记录中留下处理结果。

## 替换对话

角色身份属于目录，不属于某个聊天窗口。旧对话失效或上下文过长时：

- 关闭旧实例前完成状态和交接；无法完成时由A00根据文件重建“最后可信状态”。
- 新对话沿用同一Axx，读取文件后接班。
- 不把旧聊天中未落盘的结论当成事实。

## 退出条件

角色在本阶段任务锁定、状态回写、交接完成、租约回收后退出。退出不是删除目录；目录作为后续阶段重启时的持久化记忆。
