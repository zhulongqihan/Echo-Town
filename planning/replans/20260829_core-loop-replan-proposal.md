# 一句话结论

把《回声镇》从“按年龄阅读一条固定人生线”改成“每一世经营一个明确的小目标，并把这世形成的基础带给下一世”。

最重要的原则是：

> 叙事可以不连续，规则必须让人一眼看懂。

上一世不必把下一世的故事讲完，但必须让玩家看见：我留下了什么，以及下一世因此能做什么。

## 一、玩家每一世到底在玩什么

每一世是一局 8 回合左右的“人生经营短局”，不是从7岁读到96岁的完整年表。玩家在开局只需要理解三件事：

- 本世处境：我从哪里开始，眼前最具体的问题是什么。
- 本世目标：这一世最想完成的一件事是什么。
- 本世资源：我能用几次行动、多少钱、多少精力和哪些关系去完成它。

每回合玩家从 3 个行动中选 1 个。行动会消耗资源，换来即时收益，并明确告诉玩家它会打开或关闭什么。回合结束后进入下一个问题，直到本世结算。

## 二、建议循环

```text
选择出身/处境
    ↓
选择本世目标
    ↓
看见资源、回合和当前问题
    ↓
选择行动 → 立刻看到代价、变化、解锁/错过
    ↓
阶段危机（不是随机惩罚，而是对前面经营的回应）
    ↓
本世结算：目标完成度 + 形成的基础 + 未完成的代价
    ↓
选择 1—2 件遗产
    ↓
下一世继承预览：上一世留下什么 → 这一世能做什么
```

暂定一世 8 回合，分为“起步、经营、转折”三个阶段：

| 阶段 | 玩家在做什么 | 需要看懂的东西 |
| --- | --- | --- |
| 起步（1—2） | 认识处境，决定先补短板还是押注目标 | 哪个资源最紧、目标需要什么 |
| 经营（3—6） | 在钱、精力、关系、能力之间分配行动 | 当前收益和未来代价 |
| 转折（7—8） | 面对本世形成的危机或机会，做最后取舍 | 前面选择如何改变这次结果 |

回合数、资源上限和危机数量都先作为可调参数，不在本提案中锁死。

## 三、从“选句子”改为“选行动”

当前三选一的问题是三个按钮并排出现，但玩家不知道它们属于什么策略。新行动至少要有四层信息：

1. 我现在能做什么。
2. 现在付出什么。
3. 立即得到什么。
4. 之后会打开/关闭什么。

行动卡的结构建议统一为：

```text
行动：跟师傅学修理
代价：消耗 1 回合、1 精力；本回合少赚一笔钱
立即：手艺 +1
后续：解锁“修理铺接班”事件；本世结算可形成“手艺”遗产
```

不是所有行动都要显示最终答案，但不能把基本代价藏起来。未知部分只允许是“后果的具体内容”，不能是“按钮到底有什么用”。

## 四、每一世的最小决策层

开局不再让玩家同时面对六条抽象属性、三条方向和整座小镇。第一层只呈现四个字段：

| 字段 | 示例 | 用途 |
| --- | --- | --- |
| 处境 | 修理铺快要关门 | 告诉玩家这一局的问题是什么 |
| 目标 | 让修理铺撑到下一代 | 告诉玩家努力方向 |
| 回合 | 3 / 8 | 告诉玩家还能试几次 |
| 紧张资源 | 钱 2、精力 3、关系 1 | 让玩家知道眼前的限制 |

手艺、洞察、声望等属性不消失，但降到第二层，用来解释行动资格和结算结果，不再占据玩家第一眼的注意力。

## 五、世代继承：让“上一世”变成“下一世的工具”

一世结束时不只显示结局标题，而是先结算四种结果：

- 完成了什么：本世目标进度与阶段性成就。
- 形成了什么：能力、习惯、资产、关系和声望。
- 改变了什么：小镇地点、人物状态、可用规则。
- 留下什么：从遗产候选中选择 1—2 件带入下一世。

遗产不能只是一句回声。每件遗产必须绑定一个可操作用途：

| 遗产 | 下一世的具体作用 |
| --- | --- |
| 手艺册 | 开局手艺 +1，第一阶段多一个“教人修理”行动 |
| 铜钥匙 | 开局可进入旧修理铺，获得一条非公开行动 |
| 老客户名单 | 第一个赚钱行动收益提高，但会减少一个自由回合 |
| 阿禾的地址 | 第二阶段必定出现一次关系事件，可换取帮助或信息 |
| 湿账页 | 解锁调查类目标，但会提高本世被注意到的风险 |

下一世开局直接显示：

```text
上一世留下：手艺册
这一世因此可以：第 1 回合就开始教人修理
代价：你会从“修理铺学徒”起步，而不是“外来孩子”
```

这样跨世影响不是背景彩蛋，而是玩家下一局可以主动利用的起手牌。

## 六、叙事结构：松开连续性，保留世界性

不再要求玩家按唯一的百年谜题顺序读完整个镇子。保留三层结构：

- **本世故事**：一局内自洽，有自己的处境、目标和结算；换一世可以换主角、家庭和问题。
- **小镇基础**：桥、修理铺、学校、河道等世界状态跨世保留，并改变行动池。
- **可选长线**：玩家通过行动拿到证据、人物关系或历史碎片，逐步拼出更大的问题；没拿到也不妨碍玩完本世。

也就是说，不能连续的是“剧情阅读顺序”，必须连续的是“规则因果”和“遗产用途”。

## 七、技术架构建议

当前`getEvents()`把内容、条件、规则、反馈和渲染数据揉在一起，适合验证固定脚本，不适合作为新的世代经营骨架。新结构建议拆成四层：

```text
内容层：profiles / goals / actions / crises / legacies
规则层：可用性、代价、效果、目标进度、结算与继承
状态层：world、currentLife、encounter、history
视图层：目标栏、行动卡、结果卡、结算页、继承预览
```

核心数据模型暂定为：

```js
world = {
  generation,
  town: {},
  people: {},
  unlocks: [],
  legacyBank: [],
  history: []
}

currentLife = {
  scenarioId,
  profileId,
  goalId,
  round,
  maxRounds,
  resources: {},
  traits: {},
  relationships: {},
  activeFlags: [],
  actionLog: [],
  legacyCandidates: [],
  selectedLegacies: [],
  status: "active"
}
```

规则函数按职责拆分：`getAvailableActions()`、`resolveAction()`、`evaluateGoal()`、`resolveCrisis()`、`settleLife()`、`getLegacyCandidates()`、`applyLegacyToNextLife()`。内容数据不再由渲染函数临时拼接，方便校验“每个行动都有代价、效果和可见反馈”。

旧版存档以版本字段保留读取/回退能力；新玩法先使用独立存档版本，不强行把旧的12节点进行中人生转换成新回合制人生。

## 八、首个垂直切片

不要一开始重做整座镇。用一个能证明“继承真的改变玩法”的小切片验证：

- 1 个本世场景：修理铺能否撑到下一代。
- 3 个出身/起步条件：学徒、外来者、旧铺继承人。
- 3 个本世目标：赚钱维持、培养学徒、查清旧账。
- 8 个回合、12 个行动、3 个阶段危机。
- 6 件有实际用途的遗产。
- 连续完成 2 世，第二世至少出现 2 个第一世没有的可用行动。

通过后再扩展桥、河流、学校和更大的小镇关系网。

## 九、可玩性验收

新版本不以“内容是否全部读完”作为首要验收，而以玩家能否形成判断为准：

1. 进入首局 30 秒内，玩家能说出“我这一世想完成什么”。
2. 做出第一个行动前，玩家能说出至少一个明确代价。
3. 行动后，玩家能指出至少一个“因此打开/关闭的东西”。
4. 第一世结算时，玩家能说出自己留下的遗产如何影响下一世。
5. 第二世开局时，玩家能主动利用继承，而不是只发现文案变了。
6. 两局之间不要求重复读完相同的固定年龄节点。

如果只加提示文案而无法通过前五项，说明根因仍未解决。

## 十、明确不做的事

- 不把固定12节点改名后继续当作核心玩法。
- 不用更多隐藏阈值制造“看起来有深度”的假策略。
- 不把每一世强行串成一条唯一主线。
- 不用随机段子代替可解释的行动和反馈。
- 不在新循环验证前重做全部人物、结局、美术和发行包。
