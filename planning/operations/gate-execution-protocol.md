# 门禁执行与交付协议

本协议适用于F0B、G1至G10以及后续D0至D6。它把“继续推进”拆成可检查的文件动作。

## 开始前

1. A00读取总入口、最新交接、用户事件、决策日志和相关专题。
2. A00运行项目校验器；有错误时不得签发任务。
3. A00核对上游版本、门禁依赖、主责角色和上一门禁是否已经用户确认。
4. A00创建唯一任务简报，填写所有契约字段和目标文件。
5. A00回收过期租约，确认没有写入范围重叠。
6. 主责角色先写“已接单/工作中”的STATE，再开始长时间工作。

## 工作中

- 只修改任务`write_scope`中的文件。
- 新增结论必须区分事实、假设、推断和待用户决定。
- 跨角色意见进入PROPOSAL或REVIEW，不直接改动他人权威正文。
- 每个任务最多一次初稿和两次聚焦修订；每次修订必须对应问题清单。
- 无响应、实例关闭或迟到写入按恢复手册处理。

## 交付前

主责角色必须同时完成：

- 权威专题或指定产出文件；
- 自审记录；
- `STATE.md`；
- `HANDOFF_*.md`；
- 尚未解决的问题和精确下一步。

之后A00必须：

1. 运行项目校验器并把结果摘要写入门禁报告；
2. 检查任务配额、版本、写入范围、链接和下游影响；
3. 调度独立审查者，或在框架门禁明确允许时执行有标注的A00反向验收；
4. 对P0/P1问题发起最多两轮聚焦修订；
5. 生成门禁报告，结论只能是通过、有条件通过、退回或暂停。

## 用户门禁

任何专题即使专业审查通过，也不能自动成为锁定事实。A00必须在主窗口集中说明：

- 本轮新增了什么；
- 哪些仍是假设；
- 哪些需要用户决定；
- 有哪些P0/P1风险；
- 下一门禁会消费哪些结论。

用户确认后，A00才可以更新决策日志、总入口、专题状态和下一任务。用户退回时，只携带明确问题重新派发。

## 关闭与回滚

- 关闭任务前再次运行校验器，回收租约并把任务状态改为已完成、已回收或需重开。
- 上游变更时，所有受影响下游任务自动标记需重开；旧任务不能继续写入。
- 发现无法证明来源的文件变更时，不覆盖权威文件，转为审查材料。
- 发生范围、存档或数据契约破坏风险时，暂停当前门禁并使用最近一次可信交接恢复。
