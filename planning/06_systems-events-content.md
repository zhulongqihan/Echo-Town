# 系统、事件与内容工程

## 规划目标

把玩法与叙事转化为无歧义、可校验、可批量生产的状态和事件规则。

当前机器可读目录见[`../development/content/content-manifest.json`](../development/content/content-manifest.json)，构建校验见[`../development/content/validate_content.py`](../development/content/validate_content.py)。目录与游戏源代码共同构成当前固定内容基线。

## 必须完成

- 属性、标签、资源、关系、世界变量与隐藏状态的权威词典。
- 事件条件、权重、优先级、互斥、冷却、次数与生命周期。
- 选项成本、即时结果、延迟结果、跨局结果和可见反馈。
- 事件链、人物链、职业链、时代链与结局链。
- 重复控制、内容预算、稀有度和玩家错过内容的回收策略。
- 存档、继承、图鉴、成就与内容版本兼容规则。
- 事件模板、命名规范、静态校验和人工审查标准。

## G5验收

- 至少十个代表事件可用统一模板完整表达。
- 同一随机种子和输入可复现相同规则结果。
- 不存在依靠临时口头解释的条件或副作用。
- 内容预算能覆盖目标重玩时长且不依赖无限生成。

### 统一事件模板

每个事件必须具备：

```text
event {
  id, age, chapter, place, title, copy,
  availability { stage, world_conditions, person_conditions, required_relics },
  choices: [
    { id, label, detail, impact, immediate_effects,
      delayed_effects, cross_life_effects, feedback, failure_value }
  ],
  tags, source_owner, content_version
}
```

`availability`在事件出现前判定；`immediate_effects`在选择确认时执行；`delayed_effects`通过后续事件读取状态实现；`cross_life_effects`写入世界、人物、遗物、发现或档案；`failure_value`至少为`echo`、`discovery`、`relationship`、`relic`或`world_change`之一。当前12个事件的选择契约已在内容目录中逐项列出。

### 条件、优先级与生命周期

- 当前一世为固定年龄槽，每个年龄槽一个主事件；槽位按年龄排序，生命周期为“未出现→可选→已选→已回顾”。
- 条件只读取登记过的状态键和比较符；不存在的键默认不满足，不用口头约定隐式触发。
- 同一事件一世只能完成一次；选择确认后按钮禁用，不能重复执行副作用。
- 正式版扩展事件使用优先级：终章/主谜题 > 人物链 > 世界修复 > 记忆/发现 > 氛围；同槽互斥事件只能出现一个。
- 当前固定内容不进行概率抽签，`seed`只负责记录确定性复现标识；未来若加入受控变体，必须以`seed + 状态 + 输入`为唯一输入并可离线复现。
- 事件不使用无限冷却队列填充时长；每个事件必须属于年龄链、人物链、地点链、证据链或结局链。

### 选择结果四层

| 层 | 例子 | 玩家何时看到 |
| --- | --- | --- |
| 即时 | 身体-1、积蓄-2、胆量+1 | 选择按钮的影响提示与反馈 |
| 后续节点 | 水位线、桥面、人物态度改变 | 下一节点条件文案 |
| 跨世 | 工具箱、湿账页、阿禾来信、镇志状态 | 下一世首节点/状态栏 |
| 结局 | 四条条件结局或一页未完 | 96岁封存与历世档案 |

所有四层结果都必须在事件契约或代码显式写出；“因为气氛所以发生”不属于可接受规则。

## G5事件链与内容预算

当前固定基线为12个主事件、36个选择、5个结局、4组人物关系、6条城镇状态、至少6类遗物/发现资产。内容链分为：桥/水闸链、镇志/名字链、修理/手艺链、阿禾/灯火链、洪水/邻里链、广播/镇外回信链。

正式版内容扩充采用增量包而非无限生成：在不改变12节点主循环的前提下，先增加8个条件事件变体、24个可审计选择和至少4个人物链回收节点；每个包必须附时间线归属、状态读写、失败价值和重复控制。若产能不足，优先保留主谜题、四条结局和跨世后果，削减装饰性事件。

### 重复控制与错过回收

- 玩家已经选择过的主事件仍可在档案回看，但下一世通过世界/人物状态改变文本，不简单复制同一反馈。
- 错过一条路线不锁死终局：证据可以在后续的广播、失物清单或完整镇志中以另一条方式回收，但代价和人物关系会不同。
- 同一选择的重复不会重复增加同一遗物；数组去重，世界状态封顶，防止刷数值。
- 每局至少保留一项回声；默认结局也写入历史，失败提供下一局可验证的信息。

## G5边界案例

| 案例 | 预期行为 |
| --- | --- |
| 缺少条件字段 | 条件不满足，不静默开放事件 |
| 数值低于0或高于上限 | 归一化到词典范围，反馈仍保留 |
| 同时满足多个结局 | 按固定优先级结算，档案保留完整世界状态 |
| 重复点击已选项 | 无第二次副作用，只有已显示反馈 |
| 页面刷新/关闭 | 从本地存档恢复当前节点和反馈状态 |
| 损坏或旧版本存档 | 拒绝或迁移到v3，不覆盖有效当前存档 |
| 内容目录与代码不一致 | 构建校验失败，不允许进入发布包 |
| AI工具不可用 | 固定事件、规则和发布包完全照常运行 |
