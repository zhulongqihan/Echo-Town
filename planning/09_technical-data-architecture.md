# 技术与数据架构

## 规划目标

在需求锁定后，形成开发者无需重新决定数据归属、接口、存档和错误处理的实现蓝图。

## 必须完成

- 前端技术栈、模块边界、构建与PWA部署方式。
- 游戏状态、事件、角色、时间线、存档和版本数据格式。
- 规则引擎、随机种子、条件判定、事件选择和结果提交的数据流。
- 本地存档、迁移、校验、备份、损坏恢复与版本兼容。
- 内容编辑、静态校验、批量导入和预览工具需求。
- 性能预算、安全、隐私、日志与可选匿名分析。
- 未来移动封装或运行时AI扩展的隔离边界，不为其提前增加首版复杂度。

## G8验收

- 所有公共数据类型、输入输出和错误结果有权威定义。
- 同一存档可在支持的浏览器和版本间可靠恢复。
- 内容错误能在构建或测试阶段被发现，而非运行时静默失败。
- 技术选择能够满足离线、响应式和低性能设备边界。

## G8架构结论

当前首发采用无构建步骤的静态网页/PWA：`index.html`负责语义结构，`styles.css`负责响应式和减少动画，`game.js`负责状态、规则、渲染与本地存档，`sw.js`只负责固定应用壳缓存。正式运行不依赖账号、服务器、联网、遥测或运行时AI。

### 运行时模块边界

| 模块 | 唯一职责 | 禁止承担 |
| --- | --- | --- |
| 状态层 | 维护`world`、`currentLife`、`settings`、`screen`并负责归一化 | 不从DOM猜测规则，不调用远程服务 |
| 规则层 | 按当前世界状态生成事件、应用选择效果、计算结局 | 不读取随机网络输入，不静默吞掉内容缺失 |
| 内容层 | 提供12个固定节点、36个选择、5个结局及内容契约 | 不在运行时生成文本 |
| 视图层 | 把状态渲染成首页、事件、反馈、结算和档案 | 不直接改变存档对象 |
| 存档层 | JSON序列化、v1/v2/v3识别、迁移、校验、导入导出 | 不上传、不建立账号同步 |
| 应用壳层 | 注册Service Worker并缓存固定本地资源 | 不缓存外部域名，不拦截并转发用户数据 |

### 权威状态与数据流

状态的唯一内存根为`state`。一次选择的顺序固定为：读取当前事件 → 校验选择和阶段 → 应用固定效果 → 对属性/小镇/人物做范围归一化 → 记录选择、反馈、回声和发现 → 写入本地存档 → 渲染反馈态。反馈态的选择按钮禁用，翻页只推进`stage`；最后一页进入结算并将本世摘要追加到`world.history`。

### 存档契约

机器可读契约位于[`technical/save-contract.json`](technical/save-contract.json)。当前固定值如下：

- 存储键：`echo-town-save`；兼容读取历史键`echo-town-mvp-v1`。
- 存档版本：v3；接受v1、v2、v3，成功读取后归一化并以v3保存。
- 顶层字段：`version`、`world`、`settings`、`currentLife`、`screen`；导出额外带`exportedAt`，不改变内部契约。
- 当前人生保存`generation`、`stage`、`seed`、六项属性、方向、选择、选择文案、回声、遗物、发现、状态和最后反馈。
- 世界保存六项小镇轨道、四组人物关系、已完成世数、遗物、回声、历世摘要、发现和最后回声。
- 导入文件上限512 KiB；字符串、数组、历史条目和数值均有长度/范围上限；非法文件不替换当前状态。
- `seed`由世数和历史长度经固定哈希产生，当前版本不使用运行时随机数；它服务复现和审计，不作为安全随机数。

### 版本迁移与损坏恢复

读取流程是“读取 → JSON解析 → 顶层结构检查 → 字段归一化 → 版本升级 → 渲染”。缺失或损坏的本地值回退到安全默认值；无法解析的存档只显示空首页，不执行部分写入。导入使用临时对象，只有整体校验成功后才替换内存和本地存档，因此失败不会污染现有进度。

### 内容数据与构建校验

固定内容目录位于[`../development/content/content-manifest.json`](../development/content/content-manifest.json)，其选择契约与运行时代码一一对应；[`../development/content/validate_content.py`](../development/content/validate_content.py)检查事件排序、ID唯一、36个选择、5个结局、选择契约、运行时无随机/远程请求以及G6审校记录。内容错误应在构建前被发现，不允许运行时静默补空文本。

### 离线、隐私与安全边界

- Service Worker只缓存列入清单的本地HTML/CSS/JS/图标，缓存键升级时整体切换并激活新版本。
- 游戏业务不发起`fetch`、XHR、WebSocket或第三方脚本请求；没有账号、广告、分析SDK、远程日志和运行时AI。
- 存档只进入当前浏览器的localStorage；导出由用户主动下载，换设备通过用户自行转移JSON文件后导入。
- 本地存档不是加密保险箱；设备共享或浏览器清理可能让进度暴露或丢失，界面不承诺云同步和跨设备自动恢复。
- 导入文本在档案和反馈渲染前经过长度限制与HTML转义；不执行存档内脚本或HTML。

### 性能与兼容预算

- 首发资源为固定静态文件，不依赖打包器；首屏目标是低端移动浏览器可直接打开，交互不等待网络。
- 每次渲染只处理12节点和受限历史/列表；历史最多20世、世界回声最多120条、档案摘要最多20条。
- 支持桌面和窄屏单列布局；不使用必须横向滚动的交互。动画可由`prefers-reduced-motion`关闭，大字模式不改变规则数据。
- 技术验收以结构校验、Node语法检查、真实Chromium桌面/窄屏、断网重载、v1/v2导入、恶意/超限导入和发行包复测为准。

2. 真实浏览器通过：新建与选择自动保存、刷新恢复、损坏导入拒绝、超限导入拒绝、v2导入归一化、断网重载；失败导入后原人生仍保留1次选择。
